Part 1

プログラミングの
基礎概念

コードを書く前に「考え方」を学ぶ

プログラムとは何か

コンピュータへの命令の羅列です。

人間の指示
  1. 冷蔵庫を開ける
  2. 卵を取り出す
  3. フライパンを熱する
  4. 卵を割って入れる
  5. 焼けたら皿に盛る
プログラム
  1. ファイルを開く
  2. 1 行ずつ読む
  3. 文字を数える
  4. 結果を画面に出す
  5. ファイルを閉じる

コンピュータは指示された通りにしか動きません。
プログラマの仕事は「正確な指示を書くこと」です。

1-1 逐次処理 (Sequential)

コンピュータは命令を上から順番に実行します。

擬似コード 
PRINT "起動しました"
PRINT "処理を開始します"
PRINT "完了しました"
出力 
起動しました
処理を開始します
完了しました

ポイント: 順番を変えると結果も変わる。
コンピュータは「前後の文脈」を自動では判断しません。

1-2 分岐処理 (Branching)

条件によって実行するコードを切り替えることができます。

擬似コード 
IF weather == "sunny" THEN
    PRINT "外に出かけよう"
ELSE
    PRINT "家にいよう"
END IF
複数分岐 
IF score >= 90 THEN
    PRINT "A"
ELSE IF score >= 70 THEN
    PRINT "B"
ELSE
    PRINT "C"
END IF

IF = もし 〜 ならば
ELSE IF = そうでなく 〜 ならば
ELSE = それ以外

1-3 ループ処理 (Loop)

同じ処理を繰り返すことができます。

回数指定 (FOR) 
FOR i = 1 TO 5
    PRINT i
END FOR

-- 出力 --
1
2
3
4
5
条件指定 (WHILE) 
count = 0
WHILE count < 3
    PRINT "Hello"
    count = count + 1
END WHILE

-- 出力 --
Hello
Hello
Hello
注意: 無限ループ
終了条件を忘れると、プログラムが止まらなくなります。
→ Ctrl + C で強制終了できます。

組み合わせてみよう

1〜10 の中から偶数だけ出力する

FOR i = 1 TO 10
    IF i % 2 == 0 THEN
        PRINT i
    END IF
END FOR

-- 出力 --
2
4
6
8
10

% は「余り」を求める演算子です。
i % 2 == 0 → i を 2 で割った余りが 0 = 偶数

Part 2

プログラミングで
気にすること

実際のコードを書くときの考え方

2-1 変数とデータ型

変数とは「名前付きの箱」。データを入れて後から使えます。

name = "Alice"        -- 文字列 (String)
age  = 25             -- 整数   (Integer)
height = 1.65         -- 小数   (Float)
isStudent = TRUE      -- 真偽値 (Boolean)

リスト（配列） 
fruits = ["apple", "banana", "cherry"]
PRINT fruits[0]  -- "apple"
PRINT fruits[1]  -- "banana"
マップ（辞書） 
user = {
  "name": "Alice",
  "age": 25
}
PRINT user["name"]  -- "Alice"

配列のインデックスは 0 から始まります（0-indexed）

2-2 関数化

繰り返す処理をまとめて名前をつける仕組みです。

関数なし（コピペ地獄） 
PRINT "----"
PRINT "Hello, Alice"
PRINT "----"
PRINT "----"
PRINT "Hello, Bob"
PRINT "----"
関数あり 
FUNCTION greet(name)
    PRINT "----"
    PRINT "Hello, " + name
    PRINT "----"
END FUNCTION

greet("Alice")
greet("Bob")
関数を作るメリット
  • 再利用: 同じ処理を何度でも呼び出せる
  • 可読性: 処理に名前がついて意図が伝わる
  • 修正が楽: 1か所を直すだけで全体に反映される

引数と戻り値

FUNCTION add(a, b)     -- a, b が「引数」(入力)
    result = a + b
    RETURN result      -- RETURN が「戻り値」(出力)
END FUNCTION

x = add(3, 4)
PRINT x               -- 7

引数: 3, 4
↓
add()
↓
戻り値: 7

関数は「ブラックボックス」として考えます。

入力（引数）を渡すと、
処理して結果（戻り値）を返してくれる。

中身の実装は呼び出し側が知らなくても使える。

2-3 命名規則

変数名・関数名は意味が伝わる名前をつけましょう。

悪い例 
x = 25
y = "Alice"
z = TRUE

FUNCTION f(a, b)
    RETURN a + b
END FUNCTION
良い例 
age = 25
userName = "Alice"
isLoggedIn = TRUE

FUNCTION calculateTotal(price, tax)
    RETURN price + tax
END FUNCTION

表記スタイル
camelCase → userName, calculateTotal  （Go・JavaScript など）
snake_case → user_name, calculate_total  （Python など）
PascalCase → UserName, CalculateTotal  （クラス名など）

コードは「誰かが読むもの」


"Programs must be written for people to read, and only incidentally for machines to execute."
— Harold Abelson (SICP)

  • 未来の自分が読んで理解できるか？
  • チームメンバーが読んで意図が伝わるか？
  • 1つの関数は1つのことだけやる
  • コメントは「何をしているか」ではなく「なぜするか」を書く
Part 3

Git の基礎

コードの変更履歴を管理する

3-1 Git とは

バージョン管理システム: コードの変更履歴を記録するツール


Git なし 
project/
├── main.go
├── main_backup.go
├── main_old.go
├── main_final.go
└── main_final2.go  ← ?

どれが最新かわからない...

Git あり 
$ git log
commit a1b2c3  "APIエンドポイント追加"
commit d4e5f6  "バグ修正"
commit g7h8i9  "初期実装"

$ git checkout d4e5f6
# 過去の状態に戻れる！

いつでも過去に戻れる

Git = ローカルの履歴管理  /  GitHub = インターネット上の保管場所

3-2 基本コマンド

Step 1: 変更をステージに追加 
git add main.go        # 特定ファイルを追加
git add .              # すべての変更を追加
Step 2: コミット（セーブポイントを作る） 
git commit -m "Hello World を追加"
Step 3: リモートに送る 
git push origin main
現在の状態を確認 
git status             # 変更されたファイルを確認
git log --oneline      # コミット履歴を確認

流れ: ファイルを編集 → add でステージ → commit で記録 → push で共有

良いコミットメッセージ

悪い例 
git commit -m "修正"
git commit -m "変更"
git commit -m "あああ"
git commit -m "fix"
良い例 
git commit -m "feat: ユーザー登録APIを追加"
git commit -m "fix: ログイン時のバグを修正"
git commit -m "docs: READMEを更新"
git commit -m "refactor: 認証処理を関数化"

よく使うプレフィックス
feat: 新機能  /  fix: バグ修正  /  docs: ドキュメント  /  refactor: リファクタリング

コツ: 「このコミットは〇〇を〜する」という文章で書ける粒度がベスト

3-3 ブランチとは

作業の「分岐」を作る仕組みです。

main  ─●─────────────────●─── (本番コード)
            \                 /
feature  ────●───●───●───●    (開発中の機能)
なぜブランチを分けるのか
  • main を守る: 壊れたコードを本番に混ぜない
  • 並行作業: 複数の機能を同時に開発できる
  • レビューがしやすい: 変更内容を明確にして確認してもらえる
  • ロールバック: 問題があれば merge 前に捨てられる

ブランチの操作: ローカル

ブランチを作って移動 
git checkout -b feature/add-login
# または
git switch -c feature/add-login
ブランチを確認 / 切り替え 
git branch             # ブランチ一覧（* が現在のブランチ）
git checkout main      # main に戻る

ブランチの操作: リモート連携

ブランチを push して Pull Request を作る 
git push origin feature/add-login
# → GitHub でPRを作成 → レビュー → merge
main の最新を取り込む 
git pull origin main
作業済みブランチの削除 
git branch -d feature/add-login    # ローカル削除
git push origin --delete feature/add-login  # リモート削除

GitHub フロー（よく使われる開発の流れ）

  1. git checkout -b feature/xxx  → ブランチ作成
  2. コードを書く
  3. git add . && git commit -m "..."  → コミット
  4. git push origin feature/xxx  → push
  5. GitHub で Pull Request を作成
  6. レビューを受けて修正
  7. Approve されたら main に merge
  8. git checkout main && git pull  → 最新に更新

1人開発でもこの流れを習慣にすると、後でチーム開発に入りやすくなります。

Part 4

Go 言語の基礎

シンプルで高速な言語

4-1 Go とは

  • Google 製（2009年）
  • シンプルな構文
  • コンパイル型・高速
  • 並行処理が得意
  • 標準ライブラリが充実
使われている場所
  • Docker / Kubernetes
  • 各種 CLI ツール
  • Web API サーバー
  • クラウドインフラ

このハンズオンでは
標準ライブラリだけを使い、シンプルなプログラムから Web API まで作ります。
外部フレームワーク（Gin, Echo）は使いません。

4-2 Go プログラムの構成

package main          // このファイルが "main" パッケージであることを宣言

import "fmt"          // 標準ライブラリ "fmt" を使用（format の略）

func main() {         // プログラムのエントリーポイント（最初に実行される）
    fmt.Println("Hello, World!")
}

必須のルール
  • 実行可能なプログラムは package main から始まる
  • func main() がプログラムの入口
  • import したパッケージは必ず使わないとエラーになる
go run main.go   # ファイルを直接実行
go build         # バイナリにコンパイル

4-3 変数の宣言

// 方法 1: var キーワード（型を明示）
var name string = "Alice"
var age  int    = 25

// 方法 2: := で型推論（最もよく使う）
name := "Alice"
age  := 25

// 定数
const maxRetry = 3

基本データ型 
int     // 整数
float64 // 小数
string  // 文字列
bool    // true / false
複合型 
[]int        // スライス（配列）
map[string]int // マップ

4-4 分岐とループ

if / else 
if score >= 90 {
    fmt.Println("A")
} else if score >= 70 {
    fmt.Println("B")
} else {
    fmt.Println("C")
}
for ループ（Go に while はない） 
// 回数指定
for i := 1; i <= 10; i++ {
    fmt.Println(i)
}

// 条件指定（while 相当）
for count < 3 {
    count++
}

Go の特徴: if / for の条件式に () は不要。
{} は必須です（省略できません）。

4-5 関数の定義

// 引数あり・戻り値あり
func add(a int, b int) int {
    return a + b
}

// 複数の戻り値（Go の特徴）
func divide(a, b int) (int, error) {
    if b == 0 {
        return 0, fmt.Errorf("0 で割ることはできません")
    }
    return a / b, nil
}

func main() {
    result := add(3, 4)
    fmt.Println(result) // 7
}

今回のハンズオンでは error の扱いは省略します。
まずは「引数」「戻り値」「呼び出し」の感覚をつかみましょう。

03 ループを関数化する

03_loop_function/main.go

package main

import "fmt"

func printNumbers(from, to int) {
    for i := from; i <= to; i++ {
        fmt.Println(i)
    }
}

func main() {
    printNumbers(1, 10)
}
02 との違い: ループ処理を printNumbers 関数に切り出した。
  • from, to int → 同じ型の引数はまとめて書ける
  • main() がスッキリして「何をしているか」が一目でわかる

04 偶数・奇数の判定

04_even_odd/main.go

package main

import "fmt"

func isEven(n int) bool {
    return n%2 == 0
}

func main() {
    fmt.Println(isEven(4))  // true
    fmt.Println(isEven(7))  // false
    fmt.Println(isEven(10)) // true
    fmt.Println(isEven(13)) // false
}
ポイント
  • % → 余りを計算
  • n%2 == 0 → 余りが 0 なら偶数
  • 戻り値の型は bool
  • return で結果を返す

06 FizzBuzz

06_fizzbuzz/main.go

fizzbuzz 関数 
func fizzbuzz(n int) string {
    switch {
    case n%15 == 0:
        return "FizzBuzz"
    case n%3 == 0:
        return "Fizz"
    case n%5 == 0:
        return "Buzz"
    default:
        return fmt.Sprintf("%d", n)
    }
}
main 関数 
func main() {
    for i := 1; i <= 100; i++ {
        fmt.Println(fizzbuzz(i))
    }
}
ルール
  • 3 と 5 の公倍数 → "FizzBuzz"
  • 3 の倍数 → "Fizz"
  • 5 の倍数 → "Buzz"
  • それ以外 → 数字そのまま

FizzBuzz のロジック解説

なぜ n%15 == 0 を最初に判定するか
15 = 3 × 5 なので、15 の倍数は 3 の倍数でも 5 の倍数でもある。
後に判定すると "Fizz" か "Buzz" だけになってしまう。
switch 文: 複数の if/else if をスッキリ書ける構文 
switch {
case 条件1:   // if 条件1 に相当
    ...
case 条件2:   // else if 条件2 に相当
    ...
default:      // else に相当
    ...
}
fmt.Sprintf("%d", n): 数値 n を文字列に変換する
%d = 整数のプレースホルダー  （例: Sprintf("%d", 42) → "42"）
やってみよう
  1. 実行して 1〜100 の出力を確認しよう
  2. 7 の倍数に "Boom" を追加してみよう

07 REST API を作る

07_api_hello_world/main.go

package main

import (
    "fmt"
    "net/http"
)

func helloHandler(w http.ResponseWriter, r *http.Request) {
    w.Header().Set("Content-Type", "application/json")
    fmt.Fprintf(w, `{"message": "Hello, World!"}`)
}

func main() {
    http.HandleFunc("/hello", corsMiddleware(helloHandler))
    fmt.Println("サーバーを起動しました: http://localhost:8888")
    http.ListenAndServe(":8888", nil)
}

（corsMiddleware は省略して表示）

HTTP / API の仕組み

    ブラウザ / curl                   Go サーバー
    ─────────────                   ────────────
         │                               │
         │  GET /hello ────────────────→ │
         │                               │ helloHandler を呼ぶ
         │  {"message":"Hello, World!"} │
         │ ←──────────────────────────── │
         │                               │
サーバーの起動 
go run main.go
アクセス確認 
curl http://localhost:8888/hello
# または ブラウザで
# index.html を開く

API コードの解説

// URL パスとハンドラーを紐付ける
http.HandleFunc("/hello", corsMiddleware(helloHandler))

// ポート 8888 でサーバーを起動（ブロッキング）
http.ListenAndServe(":8888", nil)
// ハンドラー関数: リクエストが来るたびに呼ばれる
func helloHandler(w http.ResponseWriter, r *http.Request) {
    // w = レスポンスを書き込むオブジェクト
    // r = クライアントからのリクエスト情報
    w.Header().Set("Content-Type", "application/json")
    fmt.Fprintf(w, `{"message": "Hello, World!"}`)
}

  2. index.html をブラウザで開いてボタンを押す
  3. メッセージを変えてみよう（例: 自分の名前を返す）
  4. 新しいエンドポイント /bye を追加してみよう
